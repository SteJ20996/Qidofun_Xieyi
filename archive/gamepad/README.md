# 手柄支援（已封存）

v0.27（2026-10-16）封存。使用者決定暫停手柄功能的開發：遊戲不再載入手柄程式，介面上的手柄設定、參數、讀數全部拿掉，目前只用鍵盤（與滑鼠）。這裡收著 v0.15 到 v0.26 做出來的全部東西，恢復時照下面的清單放回去。

封存前最後一版是 `main` 上的提交 **`cdc5c8b`**（PR #23 合併後）。`git show cdc5c8b:src/pad.js` 之類的指令可以直接取出當時的任何檔案。

## 做到哪裡

- **v0.15**：瀏覽器 Gamepad API，Nintendo 布局（A 右、B 下、X 上、Y 左）對應成鍵盤事件，遊戲本體一行不改；面板裡十字鍵移焦點、A 按下、B 關；非標準手柄自動進精靈學一遍，按手柄 id 存在 `localStorage` 的 `xieyi.pad`。
- **v0.15.1–v0.15.3**：十字鍵是帽子軸、扳機是軸、半幅搖桿、搖桿報成四顆鍵、閒置不在零，都認得；暫停面板加校正中點、對調、反向、錄八秒讀數。
- **v0.23**：精靈每一步先等鍵放開、各軸靜下來（`STILL`=0.05、`CALM_MS`=220、`NOISY_MS`=1500），一直抖的軸當雜訊；存的對應帶 `v: 3`；條狀讀數與「設成左右／上下」。
- **v0.25**：手柄設定頁，二十個鍵位一個一個設；**v0.25.1**：點了切換過去、右上角回到主頁、手柄模擬的鍵改發在 `document`。
- **v0.26**：L3＝L（神兵）、R3＝Y（彈弓），見聞錄與睡移到右搖桿上下（`stickV`、`ryFree()`）。鍵盤的 L／P／Y 不屬於手柄，封存後照留在遊戲裡。

## 封存時的狀態：使用者最後一次的讀數

使用者的手柄在瀏覽器裡始終無法正常操作。封存前最後一張暫停面板的截圖：

```

按過的鍵 [0,1,2,3]
軸 閒置[最小,最大]（★有動）：0:0.00[0.00,0.00] 1:0.00[0.00,0.00] 2:0.00[0.00,0.00] 3:0.00[0.00,0.00]
  4:0.01[-0.91,0.81]★ 5:0.00[0.00,0.00] 6:0.00[0.00,0.00] 7:0.00[0.00,0.00] 8:0.00[0.00,0.00] 9:1.29[-1.00,1.29]★
現在的對應：A=鍵1 B=鍵0 X=鍵3 Y=鍵2 … 左搖桿=軸0，軸1 右搖桿=軸2，無
```

這幾點可能就是線索，恢復時先查：

1. **錄的八秒裡只有軸 4 與軸 9 動過**，軸 0、1 從頭到尾都是 0。對應卻還是預設的「左搖桿＝軸 0、1」，所以推搖桿人不會走。軸 4 動過整整一個來回（−0.91 到 0.81），可能就是左搖桿的某一個方向，也可能是扳機；另一個方向在瀏覽器裡也許根本沒報上來。光看一張截圖分不出來，要請使用者分別推上下、左右各錄一次。
2. **軸 9 閒置在 1.29**（正好是 9/7≈1.2857，帽子軸「沒按」的另一種寫法；Chrome 常見的是 3.2857）。`pad.js` 只把閒置值 |rest| > 1.5 的軸當帽子軸，所以這根會被當成普通的軸，十字鍵的判法就不對。恢復時把 1.2857 也算成帽子軸的閒置值。
3. **這張截圖裡的手柄名稱是原本的「Wireless Gamepad (Vendor: 0e6f …)」**，不是 Steam 模擬出來的 Xbox 手柄。所以拍這張的時候，Steam Input 的模擬沒有生效：可能不是從 Steam 啟動、那個捷徑沒開 Steam 輸入，或 Steam 沒接手這支手柄。「靠 Steam Input 解決」這條路其實還沒有驗證過。
4. 0e6f 是 PDP 這家廠商的 USB 代號（使用者先前說是 NS2 的第三方手柄）。

## 原本的玩家說明（README「按鍵」一節的手柄部分）

**手柄**（v0.15）：藍牙或 USB 把手柄連上電腦，開著遊戲按一下手柄上任一鍵，瀏覽器才會把它交給遊戲，畫面會提示「手柄已連上」。預設照 Nintendo 布局：

| 手柄 | 做什麼 |
| --- | --- |
| 左搖桿／十字鍵 | 走 |
| `A`（右） | 取／攻擊／讀／開櫃／上船；面板裡按下選中的鈕；彈窗裡等於 Enter |
| `B`（下） | 關掉面板／彈窗；沒開面板時暫停 |
| `X`（上） | 放／用／開灶（F） |
| `Y`（左） | 吃喝、穿衣甲、服丹、用錦囊（V） |
| `L`／`R`、右搖桿左右 | 上一格／下一格囊 |
| `ZL` | 換工具；拿著神兵時收回（P） |
| `ZR` | 攻擊（E，按著連打） |
| `＋` | 製作（C） |
| `－` | 地圖（M） |
| 左搖桿按下 | 拿出神兵、再按換另一件（L） |
| 右搖桿按下 | 拿出／收起彈弓（Y） |
| 右搖桿往上／往下 | 見聞錄（J）／睡（R） |

面板開著時（製作、櫃、灶、幫助、暫停、起始頁……）十字鍵或左搖桿在鈕與格子之間移紅框焦點，`A` 按下，`B` 關。手柄一連上，畫面最下面那行按鍵說明就換成手柄的。瀏覽器認得的手柄（Switch Pro、Xbox、PS 多半是）直接能用；對應不是標準的第三方手柄，第一次按鍵會自動進「手柄對應」精靈，照提示一顆一顆按（搖桿推到底），學完存在這個瀏覽器裡，下次直接用。起始頁、暫停面板、幫助裡都有「手柄設定」（v0.25）：點了就切換到設定頁，右上角「回到主頁」（遊戲裡另有「返回」回到暫停面板，進來時遊戲自動暫停）。頁上是一張二十列的表，每列寫鍵位、遊戲裡做什麼、現在綁的是哪一顆；點某一列的「設定」再按手柄上那一顆，就只換那一個（空白鍵設成無、Esc 取消）。同一顆鍵不綁兩個，新綁的佔掉別列原本用的，那一列改成無。表下面有「照順序全部學一遍」（精靈）、「全部改回標準」「校正中點」。精靈最下面一行與暫停面板最下面一行都即時顯示瀏覽器看到的東西：幾鍵幾軸、按著哪幾顆鍵、每根軸的值（離閒置超過 0.3 的標 ★）、遊戲判定成哪個方向與哪些鍵、現在的對應表；方向不對時，推著搖桿看哪根軸標了 ★，抄下那一行就能對。十字鍵做成一根「帽子軸」（閒置 3.29 或 0、八個位置各一個值）、扳機做成軸、搖桿只有半幅、搖桿做成四顆按鍵、閒置不在正中的手柄都認得；精靈把方向學錯了，沒被綁走的標準十字鍵與左搖桿仍然能走。

**暫停**（`B` 或 `Esc`）面板裡有「繼續」「生存之道」「手柄設定」「回到主頁」；回到主頁會先存檔，再回起始頁的三格存檔。手柄不聽話時，暫停面板還有一排工具：「校正中點」（以現在搖桿停的位置當零點，搖桿閒置不在零、人自己走的時候用）、「對調左右搖桿」、「左搖桿上下反向」「左搖桿左右反向」、「錄八秒讀數」（錄下每根軸的閒置與最小最大、按過的鍵、幾鍵幾軸、手柄 id，自動複製到剪貼簿，貼給開發者就能對症）。推到底只動一點點的搖桿，精靈按住一秒多也收得到，並照幅度放大。**v0.23**：精靈、手柄設定頁與暫停面板都有條狀讀數——每根軸一條（紅點是現在、短線是閒置）、每顆鍵一格（按著亮紅），推搖桿時哪一條在動一眼就看得出來；暫停面板每根軸旁邊還有「設成左右」「設成上下」，可以直接指定哪根是左搖桿（推著往右、往下時點，方向就對）。精靈每一步會等鍵放開、各軸靜下來，出現「好，請按」才收下一個；一直在抖的軸（體感、陀螺儀）會被當成雜訊不看，卡住不回中的軸也不會再把精靈卡住。舊版存的對應不再沿用（多半是學錯的），第一次接上會重學。**推左搖桿時沒有任何一條在動**，是瀏覽器讀不到這支手柄的搖桿：把手柄切到 PC／X-input 模式，或換 Firefox、Edge、Safari 試試。

## 原本的規格（docs/SPEC.md 7.2 的手柄部分）

**手柄**（v0.15，`src/pad.js`）：每幀輪詢 `navigator.getGamepads()`，第一次有動靜（按鍵或搖桿）才算連上（瀏覽器本來就要按過鍵才把手柄給頁面）。對應成鍵盤事件丟給 `window`，遊戲本體不知道手柄的存在：

| 手柄（Nintendo 布局） | 標準對應的鍵號 | 沒開面板時 | 面板開著時 |
|---|---|---|---|
| 左搖桿／十字鍵 | 軸 0、1／鍵 12–15 | 按著 W A S D（取主軸，死區 0.4） | 移焦點（第一下立刻，按著 350 ms 後每 120 ms 一步） |
| A | 1 | 按著 E | 按下焦點（鈕 click、囊格 mousedown）；沒焦點就 Enter |
| B | 0 | Esc（沒面板＝暫停） | Esc（關面板、彈窗答「不」） |
| X | 3 | F | － |
| Y | 2 | V | － |
| L／R | 4／5 | Q／Tab | － |
| 右搖桿左右 | 軸 2 | Q／Tab，按著 260 ms 連跳 | － |
| ZL | 6 | P（拿著神兵時收回） | － |
| ZR | 7 | 按著 E | － |
| ＋／－ | 9／8 | C／M | C／M（開關） |
| L3／R3 | 10／11 | L／Y（神兵、彈弓；v0.26 前是 J／R） | － |
| 右搖桿上下 | 軸 3 | 往上 J、往下 R（推一下算一下；往上下推得比左右多才算，左右亦然） | 見聞錄開著時往上＝J（關掉） |

焦點：面板由上到下找第一個沒 `hidden` 的（dead、warn、fogask、seaask、padmap、padset、help、voyage、pause、read、chest、stove、craft、map、journal、start），候選是裡面可見、沒 disabled 的 `button`、`.slot`（空的囊格不算）、`.save-card`（空格也算），紅框 `.padfocus`；一開始停在帶 `on` 的那個（選著的大類、選著的存檔格），否則第一個；面板重畫後停在原來的序號。**對應精靈**（手柄設定頁的「照順序全部學一遍」，或第一次看到 `mapping !== 'standard'` 且沒學過的手柄時自動開）：二十步，A、B、X、Y、L、R、ZL、ZR、－、＋、L3、R3、上下左右、左搖桿右、左搖桿下、右搖桿右、右搖桿下；每步要先放開再按（搖桿回中），沒有的鍵按「略過」（空白鍵），Esc 取消，「用標準對應」刪掉學過的；學完按手柄 id 存進 `xieyi.pad`。

**手柄設定頁**（v0.25，`#padset`）：起始頁、暫停面板、幫助的「手柄設定」都切換到這一頁（v0.25.1：`openPadset()` 把起始頁、暫停、幫助收起來並記在 `padBack`；遊戲裡沒暫停就先 `togglePause()`）。右上角「回到主頁」（`padsetHome()`：起始頁進來的就回起始頁，遊戲裡等於暫停面板的「回到主頁」，先存檔再回起始頁）；遊戲裡另有「返回（Esc）」（`closePadset()`，把 `padBack` 原樣放回），起始頁進來的不顯示返回，Esc 一樣回起始頁。這頁開著時捕獲階段把按鍵攔下，不給遊戲與起始頁。提示寫在頁裡的 `padset-msg`。二十列照 `STEPS` 的順序，每列是鍵位名（`ENTRY_NAME`）、遊戲裡做什麼（`ENTRY_DOES`）、現在綁的（`friendly()`：鍵號、`軸 i 到 at`、`軸 i（反向），幅度 s`、`鍵 a／b`、無）與「設定」鈕；沒看到手柄時鈕是灰的、上面寫「還沒看到手柄」。點「設定」走 `learnOne(name)`：跟精靈同一套判法（`learnStep`，等鍵放開、各軸靜下來、雜訊軸不看），只是只有一步、不排除已被別的項目用掉的鍵與軸（`L.single`）；那一列變成「等你按……」並標紅，狀態行寫「請按「A」（空白鍵＝設成無，Esc＝取消）」，搖桿寫「請把左搖桿往右推到底」。收到後 `finishOne()` 合進現在的對應：別的鍵位用同一顆鍵、軸上同一個值（差不到 0.15），或別的搖桿用同一根軸、同一顆鍵，一律改成 −1／`null`（無），並在提示裡列出；學到的軸的閒置值合進 `rest`；存檔（`persist()`，帶 `v: 3`）。剛按的那顆還按著時不當成新的一下（`down` 照現況填好），免得在面板裡又按到焦點上的「設定」。搖桿設成無（空白鍵）就是 `null`，讀值一律 0。底下的鈕：「照順序全部學一遍」暫時收起這頁開精靈（學完或取消回到這頁，`L.back`）、「全部改回標準」（`useStandard()`，連存的對應一起刪）、「校正中點」、「好了（Esc）」。這頁開著時每幀畫條狀讀數（`padset-bars`）；非標準手柄連上時若這頁開著，不自動開精靈。

**精靈的基準**（v0.23）：每一步開始前先等鍵放開、上一步收的那根軸離開學到的值，再等各軸 `CALM_MS`=0.22 息內晃動不到 `STILL`=0.05，把那時的各軸當這一步的基準（`L.base`）；等了 `NOISY_MS`=1.5 息還靜不下來的軸標成雜訊（`L.noisy`，體感、陀螺儀這類），之後不看；搖桿步只挑還沒被十字鍵、扳機、別的搖桿用掉的軸；學到的軸用那一步的基準當閒置值（`L.restOf`）。面板上一行狀態寫「先放開，等一下」「等搖桿與手柄靜下來」「好，請按」。**條狀讀數**（`liveBars()`）：精靈與暫停面板，每根軸一條（−1 到 1，短線是閒置、紅點是現在，帽子軸閒置 3.29 寫「閒置」）、每顆鍵一格（按著亮紅）；暫停面板的每根軸旁邊有「設成左右」「設成上下」（`assign()`）：推著往右（往下）時點，方向照推的方向，沒推著點就是正向，不對再按反向。
**第三方手柄的怪事**（v0.15.1、v0.15.2）：對應的每個鍵可以是鍵號、`{ax, at}`（軸上的一個值）或 −1；搖桿是 `[軸, 正負]` 或 `{pos, neg}`（兩顆鍵）。`{ax, at}` 的判定看該軸閒置值 `rest`：閒置 |rest| > 1.5 是 Chrome 的帽子軸（閒置 3.2857，上 −1、右 −0.4286、下 0.1429、左 0.7143，斜角在中間），取與學到的值繞圈距離 < 0.3，斜角同時算到相鄰兩向；其他軸（扳機、閒置 0 的帽子軸、數位搖桿）看 |v − at| 是否不超過 `min(0.35, max(0.12, |at − rest| / 2))`。搖桿一律讀相對閒置值：精靈在第一個沒按鍵的幀記下各軸閒置值，沒學過的手柄第一眼看到時把所有 |v| ≤ 1 的軸現值記成閒置值（v0.15.3；之前只信 |v| < 0.3，閒置 0.9 的軸會讓人自己走）；|v| > 1.5 的軸不當搖桿。搖桿綁法可帶第三個值 `span`（學到時推到底離閒置的幅度，< 0.95 才記），執行期 `(v − rest) × 正負 ÷ span` 夾在 ±1，推到底只動 0.1 的搖桿也走得動。方向的順序：學到的十字鍵上下左右、左搖桿主軸；都沒有而且是學過的對應時，再看沒被任何綁法用到的標準十字鍵（鍵 12–15）與標準左搖桿（軸 0、1，相對閒置超過 0.6），精靈學錯也走得動。「連上」的判定扣掉閒置值，帽子軸閒置的 3.29 不算動靜。手柄從列表消失九十幀算斷了：放掉按著的鍵、按鍵列換回鍵盤、精靈取消。精靈步驟：搖桿那步收「離閒置動得最多的軸」（門檻 0.3，先挑不是帽子軸的）；沒有軸動過 0.3 時，若有軸離閒置動了超過 0.03 且同一根軸持續 1.2 秒，收它並記幅度；都沒有就收一顆沒用過的鍵，並在後面插一步問反方向；鍵那步先收鍵，沒鍵就收動得最多的軸記成 `{ax, at}`。暫停面板的工具列（v0.15.3）：「校正中點」`recenter()` 把現在各 |v| ≤ 1 軸的值當閒置值並存成自訂對應；「對調左右搖桿」`swapSticks()`；「左搖桿上下／左右反向」`flip('ly'／'lx')`（軸就反正負，兩顆鍵就對調）；「錄八秒讀數」`record()`：八秒內記各軸閒置與最小最大、按過的鍵，結束寫進 `#pause-rec` 文字框並 `navigator.clipboard.writeText`，格式「山海有形手柄讀數 v2 | id | 對應 | 幾鍵幾軸 | 按過的鍵 | 軸 閒置[最小,最大]★ | 現在的對應」。讀數：精靈的 `#padmap-live` 與暫停面板的 `#pause-live` 每幀寫「瀏覽器看到：id · 對應 · 幾鍵幾軸 · 按著的鍵 · 每根軸的值（離閒置超過 0.3 標 ★）· 判定：方向與鍵 · 現在的對應表」。連上手柄時 `#keys` 換成手柄的說明；暫停面板與起始頁都有「手柄對應」鈕；暫停面板的「回到主頁」先 `save()` 再 `location.reload()`，起始頁會選著剛才那格。

### 用 Steam 測手柄（不用先付上架費；桌面版說明原文）

Steam 會把各種手柄模擬成 Xbox 手柄交給從 Steam 啟動的程式（Steam Input）。第三方手柄在瀏覽器裡對不上的問題，很可能在這裡就消失了。這一點還沒在真機上驗證過，所以要測：

1. Steam 左下角「新增遊戲」→「新增非 Steam 遊戲」→「瀏覽」→ 選 `ShanHaiYouXing.exe` → 加入。
2. 收藏庫裡對它按右鍵 →「內容」→「控制器」→ 把「覆寫 Steam 輸入」設成「啟用 Steam 輸入」。
3. **從 Steam 裡**按「開始」（直接點 exe 開不會經過 Steam Input）。
4. 按一下手柄任一鍵，到起始頁的「手柄設定」：
   - 上面一行寫「手柄：Xbox 360 Controller（標準對應…）」之類，就是 Steam 接手了。
   - 推左搖桿，看下面的條狀讀數有沒有在動，再進遊戲走走看。
5. 把結果（第 4 步那一行字、條有沒有動、走得動嗎）告訴我。
